# 远程文档定时更新流程

## 概述

远程文档定时更新是指系统通过配置 cron 表达式，周期性检测远程 URL 文档是否发生变化，若有变化则自动下载并重新执行分块入库流程。

## 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│          KnowledgeDocumentScheduleJob.scan()               │
│                  (每 10 秒扫描一次)                          │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│              ScheduleRefreshProcessor.process()             │
│                   (执行更新主流程)                           │
│  Phase1: 锁获取与预检                                        │
│  Phase2: 变更检测                                             │
│  Phase3: 文档占用与文件上传                                    │
│  Phase4: 重新分块                                             │
│  Phase5: 状态写回                                             │
└─────────────────────────────────────────────────────────────┘
```

## Phase 1：调度扫描

**入口**：`KnowledgeDocumentScheduleJob.java:63`

```java
@Scheduled(fixedDelayString = "${rag.knowledge.schedule.scan-delay-ms:10000}")
public void scan() {
    List<KnowledgeDocumentScheduleDO> schedules = scheduleMapper.selectList(
        new LambdaQueryWrapper<KnowledgeDocumentScheduleDO>()
            .eq(KnowledgeDocumentScheduleDO::getEnabled, 1)
            .le(KnowledgeDocumentScheduleDO::getNextRunTime, now)  // 到期任务
            .lt(KnowledgeDocumentScheduleDO::getLockUntil, now)    // 锁已释放
    );

    for (KnowledgeDocumentScheduleDO schedule : schedules) {
        ScheduleLockLease lease = lockManager.tryAcquire(schedule.getId(), now);
        if (lease != null) {
            knowledgeChunkExecutor.execute(() -> scheduleRefreshProcessor.process(lease));
        }
    }
}
```

**扫描条件**：
- `enabled = 1` 已启用
- `next_run_time <= 当前时间` 已到执行时间
- `lock_until 为空或已过期` 锁可获取

**兜底机制**：`recoverStuckRunningDocuments()` 每 60 秒恢复因进程崩溃卡在 `RUNNING` 状态的文档

## Phase 3：变更检测

**入口**：`RemoteFileFetcher.java:79`

```java
RemoteFetchResult fetchResult = remoteFileFetcher.fetchIfChanged(
    sourceLocation,
    lastEtag,           // 上次记录的 Etag
    lastModified,       // 上次记录的 Last-Modified
    lastContentHash,    // 上次记录的内容哈希
    docName
);
```

**检测逻辑（三层防护）**：

```java
// 1. HEAD 请求预检
HttpHeadResponse headResponse = tryHead(url);
String etag = headResponse.etag();
String lastModified = headResponse.lastModified();

// 2. 比较 Etag
if (etag != null && etag.equals(lastEtag)) {
    return RemoteFetchResult.skipped("远程文件未变化");
}

// 3. 比较 Last-Modified
if (lastModified != null && lastModified.equals(lastModified)) {
    return RemoteFetchResult.skipped("远程文件未变化");
}

// 4. 下载文件并计算 SHA-256 内容哈希
Path tempFile = Files.createTempFile("knowledge-schedule-", ".tmp");
MessageDigest digest = MessageDigest.getInstance("SHA-256");
// ...
String hash = hexEncode(digest.digest());

if (hash.equals(lastContentHash)) {
    return RemoteFetchResult.skipped("内容哈希未变化");
}
```

**任一层相同则跳过本次更新，避免无意义的下载和分块**

## 错误处理

| 场景 | 处理方式 |
|------|----------|
| 锁续约失败 | 立即停止，释放锁，防止死锁 |
| 文档正在分块中 | 跳过本次调度 |
| 分块失败 | 文档状态回退为 FAILED，保留新文件待处理 |
| 进程崩溃 | 60 秒后台扫描将 RUNNING 超时的文档重置为 FAILED |
| 文件切换后写回失败 | 仅记录执行成功，调度状态待修复 |

## 文件清理规则

```java
// 成功后删除旧文件
deleteOldFileQuietly(oldFileUrl, newFileUrl) {
    if (oldFileUrl != newFileUrl) {
        fileStorageService.deleteByUrl(oldFileUrl);
    }
}
```

## 配置示例

```yaml
# 上传远程文档时配置
sourceType: "URL"
sourceLocation: "https://example.com/doc.pdf"
scheduleEnabled: 1              # 启用定时拉取
scheduleCron: "0 */6 * * *"     # 每6小时检查更新
```

## 三层防重机制

| 层级 | 机制 | 作用 |
|------|------|------|
| 调度层 | 分布式锁 `ScheduleLockManager` | 多节点不重复执行 |
| 文档层 | 状态机 `tryMarkRunning()` | 与手动分块操作互斥 |
| 文件层 | Etag + Last-Modified + SHA-256 | 避免无意义的重复下载和分块 |

## 关键实体

### KnowledgeDocumentScheduleDO

存储定时调度的配置信息

| 字段 | 说明 |
|------|------|
| doc_id | 关联的文档 ID |
| cron_expr | cron 表达式 |
| enabled | 是否启用 |
| next_run_time | 下次执行时间 |
| last_run_time | 上次执行时间 |
| last_success_time | 上次成功时间 |
| last_etag | 上次文件的 Etag |
| last_modified | 上次文件的 Last-Modified |
| last_content_hash | 上次文件的内容哈希 |
| last_status | 上次执行状态 (SUCCESS/SKIPPED/FAILED) |
| lock_until | 锁过期时间 |
